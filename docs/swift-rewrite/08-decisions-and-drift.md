# 08 — Decisions and Drift Register

Every item below is a decision the owner should confirm (or override) before the one-shot build
runs. Each has a short **id** usable verbatim inside a `[DECISION: <id>]` tag anywhere in `02`–`07` or `09`,
the **evidence** that raised it, the **default** the plan assumes, the **alternative**, and the
**impact** of getting it wrong.

There are **127** numbered entries (§1), **16** bug ids that are fixed forward rather than reproduced
(§2), and **20** documentation-drift rows `D1`–`D20` (§3). Those three sets are the complete id
namespace: **there are no aliases** (§4). Entries **#101–#127** live in §1.5 and come from
`09-native-polish-and-platform-features.md` — the haptic map, the modern-platform surfaces, the
accessibility floor and the motion policy.

Reading the defaults column top to bottom gives the complete set of assumptions the AI coding agent
must hold. `07-one-shot-prompt.md` restates them in condensed form; **this file is authoritative**
if the two ever disagree.

The governing rule, from the owner: **fidelity target is the current code's behaviour, not the
in-app documentation.** Where the original's docs and the original's code disagree, the code wins
and the disagreement is listed in §3. Where the current code is simply wrong, see §2 — those are
fixed forward rather than reproduced.

## 4. Tag ids are canonical — there are no aliases

Every `[DECISION: <id>]` tag in `02`–`07` and `09` names, verbatim, either a numbered entry in §1 (#1–#127), an
id in the bug list in §2, or a row id (`D1`–`D20`) of the drift table in §3. The normalization table
that used to sit here — mapping earlier-draft spellings such as `ipad-split-view`,
`gallery-no-nsfw-blur`, `force-nsfw-account-settings`, `hls-url-entity-decoding` or
`mark-seen-restart` onto their canonical ids — has been applied to those documents and deleted.

**One id has been retired and replaced rather than renamed.** An earlier draft of #6 deferred iPad and
the split view, and was spelled accordingly. The owner reversed that decision: iPad and the split view
are **in scope**, and the only id for that subject is now `ipad-split-view-in-scope` (#6). The retired
spelling appears nowhere in `00`–`08`; if you encounter it, it is stale text from before the reversal,
not a decision, and the behaviour it describes — a phone-only build with the split view omitted — is wrong.

Reading rules for the coding agent:

1. **This register is the specification for every tagged behaviour.** Where a `04*` or `09` document's prose
   and this register's "Default (assumed)" column ever read differently, the register wins; the `04*`
   documents have been reconciled to it, so a divergence is a defect in the set, not a choice.
2. **A tag naming an id that appears nowhere in §1, §2 or §3 is an error.** Treat the behaviour as
   "match the current code as described in `spec/`", and record the tag in `PROGRESS.md` under
   "Open questions". Do not invent a register entry at build time.
3. **Gate ids are a separate namespace.** `gate.*` identifiers belong to `05-monetization.md` §4 and
